## Remaining gaps (no runnable official KAT through the KMS's own API)

|Primitive|Why no official KAT runs|What covers it today|
|---|---|---|
|ML-KEM encapsulation|`ml_kem_encapsulate` cannot take the ACVP randomness `m`|keygen + decaps KATs above|
|ML-DSA / SLH-DSA signing|`ml_dsa_sign` signs hedged with empty context; no deterministic or context option|verify KATs above, seeded-keygen KAT (ML-DSA)|
|SLH-DSA key generation|OpenSSL seed parameter is testing-only (`pqc/mod.rs` ~L244); KMS keygen is unseeded|verify KATs|
|ACVP ML-KEM decapsulation with raw `dk`|KMS loads PKCS#8 only; raw `dk` would need `load_raw_private_key` (pub(crate), unsafe pointer)|Wycheproof seed-based decaps|
|Hybrid KEMs X25519MLKEM768 / X448MLKEM1024, ConfigurableKEM, Covercrypt|no NIST/IETF-final KAT for these exact constructions|round-trip tests, `kat/covercrypt_decrypt` self-generated vector|
|ECIES (NIST curves, SHAKE128 KDF) and Salsa sealbox|Cosmian/libsodium constructions without an official KAT|round-trip tests|
|CKM_RSA_AES_KEY_WRAP|PKCS#11 composition (OAEP + KWP) with no published KAT|OAEP and KWP KATs above|
|ECDSA signing on P-384/P-521 and in FIPS builds|randomized `k`; only the non-fips P-256 RFC 6979 path is deterministic|verify KATs above|
|RSA-PSS signing|random salt|verify KATs above|
|ECDSA with SHA-224/SHA-3, P-224|`ecdsa_verify` maps only SHA-256/384/512|not exposed|
|RSA verify with SHA-224|`rsa_verify` rejects SHA-224 (`NotSupported`); signing supports it|CAVP sign KAT|
|X448 key agreement|no KMS function performs X448 agreement|not exposed|
|Ed448 signing|ACVP Ed448 SigGen groups all use a non-empty context, Wycheproof has no private keys; `eddsa_sign` has no context parameter|Ed448 verify KAT|
|HKDF / PBKDF2 with SHA-3|`get_md` / `get_message_digest` reject SHA-3|not exposed|
|Argon2id|parameters fixed (t=2, m=19456 KiB, p=1); RFC 9106 §5.3 uses t=3, m=32, p=4 with secret/AD|`test_password_derivation_argon2id_kat` self-KAT|
|FF1 with 18 rounds (`FF1h`, production)|non-standard round count|NIST samples + ACVP KAT on `FF1fr<10>`|
|Concat KDF (JOSE ECDH-ES)|ACVP KDA-OneStep fixedInfo patterns do not map onto the JWA AlgorithmID/PartyU/PartyV encoding|RFC 7518 App. C unit test|
|CTR-DRBG (`KmsRng`)|OpenSSL RAND takes no injected entropy|FIPS provider power-on self-tests|
|SHAKE-128 (ECIES-internal)|not exposed standalone|none|
|KMIP-level vectors (`vectors/kat/**`)|no TTLV vector yet for RSA-PSS/PKCS#1 sign, ECDSA P-384/521, X25519 DeriveKey, ML-KEM, ML-DSA, SLH-DSA|crypto-layer KATs above|

## Deviations the vectors exposed

- `ecdh_key_agreement` rejects an all-zero shared secret on purpose; the valid Wycheproof records `wycheproof-ecdh_secp{256r1,384r1,521r1}-3` produce exactly that, so `test_ecdh_official_vectors` asserts `Err` for them.
- The RSA signing path mapped SHA-224 to SHA-256 (fixed in `rsa/sign.rs`).
